## Summary

The pipeline output matches what `enumerate_downstream.py` produces, but that code is wrong for transcripts whose CDS features have **GFF phase 1**.

It slices the transcript using `cds_offsets.py` (which matches current `annotation.gff3`) and translates from the first base of that slice. For phase 1, the reading frame starts one nucleotide **before** the CDS (last base of the 5′ UTR). Ignoring phase misaligns codons for the downstream peptide on those transcripts.

**Mechanism:** `cds_phase_ignored`

**Magnitude:** `start_offset` values are still correct (they use `(CDSPOS−1)//3` on the annotated CDS); only the peptide sequence is wrong. So **0 codons**, direction **none**.

**Affected (7 variants, all phase‑1 transcripts):**  
`ENST00000000003:88`, `ENST00000000005:275`, `ENST00000000007:112`, `ENST00000000008:285`, `ENST00000000009:259`, `ENST00000000010:260`, `ENST00000000012:155`

**Unaffected (5 variants, phase 0):**  
`ENST00000000001:292`, `ENST00000000002:81`, `ENST00000000004:311`, `ENST00000000006:83`, `ENST00000000011:136`

Correct peptides were computed by prepending `phase` nucleotides from upstream of the CDS start, applying each indel at `CDSPOS` within the annotated CDS, and translating the downstream tail through the standard genetic code (stop at first `*`).

Full results are in [`output/submission.json`](output/submission.json).
